# Feature planning workflow

1. Clarify the requested outcome, non-goals, target users, constraints, and definition of done.
2. Inspect relevant code and docs; identify stack and existing patterns from evidence.
3. Create user stories and testable acceptance criteria, including validation, permissions, error/loading/empty states, accessibility, responsive behavior, observability, and migration concerns when relevant.
4. Delegate independent reviews to requirements, architecture, database, API, security/threat-modeling, UX, and testing agents as appropriate.
5. Document proposed design, alternatives, impacted files/modules, API/data changes, rollout/rollback, tests, risks, and unresolved questions.
6. Do not implement until the user approves the plan for material changes.
