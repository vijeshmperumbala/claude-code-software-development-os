# Requirements Traceability Skill

## Purpose
Maintain a verifiable chain from approved requirements to implementation and tests.

## Workflow
1. Assign stable requirement IDs and make acceptance criteria observable.
2. Link each requirement to TODO/task IDs, relevant design/ADR, implementation paths, and test IDs.
3. Identify unimplemented, untested, ambiguous, and out-of-scope requirements separately.
4. On completion, report evidence and mark each requirement `PASS`, `FAIL`, `BLOCKED`, `NOT RUN`, or `NOT APPLICABLE`.
5. Never infer satisfaction from code existence alone; require test or review evidence.
