# Requirements-to-Test Traceability

1. Capture approved requirements with stable IDs and testable acceptance criteria.
2. Link requirement IDs to TODO/task IDs, design decisions, changed paths, test cases, and verification evidence.
3. At plan review, flag requirements with no planned implementation or test.
4. At implementation review, flag changed behavior without requirement or justified maintenance reference.
5. At acceptance, mark each criterion PASS/FAIL/BLOCKED/NOT RUN/NOT APPLICABLE and cite evidence.
6. Keep requirement completion distinct from deployment completion. Changes in scope require renewed user approval when material.
